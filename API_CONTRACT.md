# API-контракт Dressly

Спецификация бэкенда для существующего фронтенда (Next.js). Документ
самодостаточен: реализовывать бэкенд можно, не читая код фронтенда.

---

## 1. Общие сведения

| Параметр           | Значение                                            |
| ------------------ | --------------------------------------------------- |
| Базовый префикс    | `/api/v1`                                           |
| Формат             | JSON, UTF-8                                         |
| Аутентификация     | Bearer JWT в заголовке `Authorization: Bearer <token>` |
| Даты               | ISO 8601 с часовым поясом, например `2026-10-07T16:57:34.667379Z` |
| Денежные значения  | Строки, 2 знака после запятой: `"59.90"`            |
| HTTP-клиент        | axios, baseURL = `/api/v1` (на клиенте), `http://127.0.0.1:8000/api/v1` (на сервере) |

Фронтенд обращается к относительному `/api/v1`, а reverse-proxy (Next.js
`rewrites`) пересылает эти запросы на бэкенд. Поэтому **CORS в разработке
не требуется**. В production бэкенд стоит за одним origin — либо так же
проксируется, либо настраивается CORS на домен фронтенда.

### 1.1 Формат ошибок

Единый формат для всех ошибок:

```json
{ "detail": "Товар не найден" }
```

При валидации входных данных `detail` — массив объектов:

```json
{
  "detail": [
    {
      "type": "greater_than_equal",
      "loc": ["body", "price"],
      "msg": "Input should be greater than or equal to 0",
      "input": -5
    }
  ]
}
```

Фронтенд читает `detail` как строку; если это массив — берёт `detail[0].msg`.

### 1.2 Коды ответов

| Код | Когда                                                              |
| --- | ------------------------------------------------------------------ |
| 200 | Успех                                                              |
| 201 | Создание ресурса                                                   |
| 400 | Семантически некорректный запрос (ссылка на несуществующую категорию, размер не в списке доступных) |
| 401 | Нет токена, токен невалиден или просрочен                            |
| 403 | Токен валиден, но прав недостаточно; либо аккаунт заблокирован      |
| 404 | Ресурс не найден                                                   |
| 409 | Конфликт: дубль slug, превышение остатка на складе, удаление категории с товарами |
| 422 | Ошибка валидации полей (несоответствие схеме)                        |
| 500 | Внутренняя ошибка. Тело: `{ "detail": "Внутренняя ошибка сервера" }` |

Ошибка 500 не должна раскрывать внутренние детали (стектрейс, SQL, пути).

### 1.3 Связка с фронтендом

| Слой фронтенда | Что ожидает от бэкенда |
| -------------- | --------------------- |
| `src/lib/apiClient.ts` | Интерцептор подставляет `Authorization` из localStorage |
| `src/services/endpoints.ts` | Формы путей и query-параметров |
| `src/types/card.type.ts` | TypeScript-типы = контракт ниже |
| `src/store/authStore.ts` | `login` → `register` → `login` → `getMe` |
| `src/store/cartStore.ts` | Операции возвращают **всю корзину**, а не изменённый объект |

## 2. Аутентификация

Модель: пара токенов. Access — короткоживущий, для каждого запроса в
заголовке. Refresh — долгоживущий, для обновления.

Access-токен **нельзя** использовать там, где требуется refresh, и наоборот.
Фронтенд полагается на это: истёкший access-токен приводит к 401 и
разлогину, а не к тихой подмене сессии.

Рекомендуемые сроки: access 24 ч, refresh 30 дней. Оба — JWT, HS256.

Токены кладутся в localStorage под ключом `dressly_tokens`:

```json
{ "access_token": "...", "refresh_token": "..." }
```

### `POST /api/v1/users/register`

Регистрация нового пользователя. Публичный.

Тело:

```json
{
  "username": "demo",
  "email": "demo@dressly.ru",
  "password": "demo12345",
  "full_name": "Иван"
}
```

| Поле        | Тип   | Обяз. | Правила |
| ----------- | ----- | ----- | ------- |
| `username`  | string | да | 3–32 символа, только `[a-zA-Z0-9_]` |
| `email`     | string | да | валидный email, уникальный |
| `password`  | string | да | 8–128 символов, минимум одна буква и одна цифра |
| `full_name` | string | нет | до 128 символов |

Ответ `201`:

```json
{
  "id": 2,
  "username": "demo",
  "email": "demo@dressly.ru",
  "full_name": "Иван",
  "role": "user",
  "is_active": true,
  "created_at": "2026-10-07T16:57:34.667379Z"
}
```

Поля `id`, `username`, `email`, `role`, `is_active`, `created_at` обязательны;
`full_name` может быть `null`. **Пароль и его хеш в ответе не возвращаются.**

Ошибки: `409` — логин или email уже заняты.

### `POST /api/v1/users/login`

Тело:

```json
{ "username": "demo", "password": "demo12345" }
```

Ответ `200`:

```json
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "eyJhbGciOi...",
  "token_type": "bearer",
  "expires_in": 86400
}
```

`expires_in` — время жизни access-токена **в секундах**.

Ошибки:
- `401` — неверный логин или пароль;
- `403` — аккаунт заблокирован (`is_active: false`).

**Важно:** для несуществующего пользователя и неверного пароля тело
ответа должно быть идентично. Иначе перебором логинов можно проверить,
какие аккаунты существуют.

### `POST /api/v1/users/refresh`

Refresh-токен передаётся в заголовке:

```
X-Refresh-Token: <refresh_token>
```

Тело: пустое `{}`.

Ответ `200` — тот же формат, что и у `/login`.

Ошибка `401`, если токен невалиден, просрочен или является access-токеном.

### `GET /api/v1/users/me`

Требует `Authorization`. Возвращает объект пользователя в формате
регистрации.

Ошибка `401` без валидного access-токена, `403` для заблокированного.

## 3. Товары

### `GET /api/v1/products`

Публичный. Список с фильтрами, сортировкой и пагинацией.

**Важно:** ответ — объект-конверт `{ items, meta }`, а не голый массив.
Фронтенд читает `page.items` и `page.meta.total`.

Query-параметры:

| Параметр    | Тип    | По умолчанию | Правила |
| ----------- | ------ | ------------ | ------- |
| `limit`     | int    | 20 | 1–100 |
| `offset`    | int    | 0 | ≥ 0 |
| `search`    | string | — | до 100 символов, регистронезависимо |
| `category`  | string | — | **slug** категории, не id |
| `min_price` | number | — | ≥ 0 |
| `max_price` | number | — | ≥ 0 |
| `in_stock`  | bool   | false | `true` — только товары с остатком > 0 |
| `sort`      | string | `newest` | `newest`, `price_asc`, `price_desc`, `name`, `popular` |

`search` ищет по `name`, `brand`, `description` — регистронезависимо.

Ответ `200`:

```json
{
  "items": [ /* массив объектов Product */ ],
  "meta": {
    "total": 42,
    "limit": 20,
    "offset": 0,
    "has_more": true
  }
}
```

`meta.total` — количество записей **после применения всех фильтров**,
без учёта `limit`/`offset`. `has_more` = `offset + len(items) < total`.

Пустой каталог — `200` с `"items": []`, не 404.

### `GET /api/v1/products/{id}`

Публичный. Один товар. Ответ `200` — объект Product. Отсутствие — `404`.

### `POST /api/v1/products`

**Требует роль `admin`.** Без токена — `401`, с обычным пользователем — `403`.

Тело:

```json
{
  "name": "Новый Худи",
  "slug": "novyy-hudi",
  "description": "Мягкий худи свободного кроя",
  "brand": "Nike",
  "price": "59.90",
  "discount_percent": 10,
  "image_url": "https://images.unsplash.com/photo-1",
  "images": [],
  "sizes": ["S", "M", "L"],
  "colors": ["Чёрный", "Серый"],
  "stock": 24,
  "category_id": 1
}
```

| Поле               | Тип     | Обяз. | Правила |
| ------------------ | ------- | ----- | ------- |
| `name`             | string  | да | 1–128 символов, после обрезки пробелов не пустой |
| `price`            | number  | да | ≥ 0, 2 знака после запятой |
| `image_url`        | string  | да | до 512 символов |
| `category_id`      | int     | да | ≥ 1, должен существовать |
| `slug`             | string  | нет | до 128; если не передан — генерируется из `name` |
| `description`      | string  | нет | до 5000, по умолчанию `""` |
| `brand`            | string  | нет | до 64 |
| `discount_percent` | int     | нет | 0–100 |
| `images`           | string[] | нет | по умолчанию `[]` |
| `sizes`            | string[] | нет | по умолчанию `[]` |
| `colors`           | string[] | нет | по умолчанию `[]` |
| `stock`            | int     | нет | ≥ 0, по умолчанию 0 |

Ответ `201` — объект Product.

Ошибки: `400` — категория не существует; `409` не используется (при
коллизии slug к `slug` добавляется числовой суффикс автоматически,
ответ приходит с `201`).

**Требования к slug.** Транслитерация кириллицы в латиницу, пробелы и
пунктуация → дефисы, повторные дефисы схлопываются, регистр понижается.
`"Новый Худи"` → `novyy-hudi`. Транслитерация должна покрывать русский
алфавит целиком. Уникальность в пределах таблицы.

### `PATCH /api/v1/products/{id}`

**Требует роль `admin`.** Частичное обновление: передаются только
изменяемые поля. Поля со значением `null` **игнорируются** (это позволяет
не различать «не передано» и «передать null»).

Ответ `200` — объект Product. Ошибки как у создания, плюс `404`.

### `DELETE /api/v1/products/{id}`

**Требует роль `admin`.** Ответ `200`:

```json
{ "message": "Товар удалён" }
```

Если на товар ссылаются позиции корзины — вернуть `409`, а не удалять
каскадно.

### Объект Product

```json
{
  "id": 3,
  "name": "Худи Oversize",
  "slug": "hoodie-oversize",
  "description": "Мягкий худи свободного кроя из хлопка",
  "brand": "Nike",
  "price": "59.90",
  "discount_percent": 10,
  "final_price": "53.91",
  "image_url": "https://images.unsplash.com/photo-1556821840-3a63f95609a7",
  "images": [],
  "sizes": ["S", "M", "L", "XL"],
  "colors": ["Чёрный", "Серый"],
  "stock": 24,
  "is_active": true,
  "category_id": 1,
  "category": {
    "id": 1,
    "name": "Мужская одежда",
    "slug": "men"
  },
  "created_at": "2026-10-07T16:57:34.667379Z",
  "updated_at": "2026-10-07T16:57:34.667379Z"
}
```

Требования:

- `final_price` — вычисляемое поле, **не хранится** в БД.
  Формула: `price × (100 − discount_percent) / 100` с округлением до
  копеек. При `discount_percent = null` равна `price`.
  Округление — половина кверху, результат всегда с двумя знаками.
- `category` — вложенный объект категории или `null`. Фронтенд
  использует `category.slug` для группировки.
- Все поля присутствуют в ответе. Отсутствующие — `null` или `[]`,
  но не отсутствуют как ключи.
- `is_active` — soft-delete. Флаг `false` означает, что товар скрыт
  из выдачи и недоступен для добавления в корзину.

## 4. Категории

### `GET /api/v1/categories`

Публичный. Ответ `200` — массив, **без конверта**:

```json
[
  {
    "id": 1,
    "name": "Мужская одежда",
    "slug": "men",
    "description": "Рубашки, футболки, брюки и куртки",
    "products_count": 12,
    "created_at": "2026-10-07T16:57:34.667379Z",
    "updated_at": "2026-10-07T16:57:34.667379Z"
  }
]
```

`products_count` — количество товаров в категории (всех, включая
неактивные).

### `GET /api/v1/categories/{id}` — один объект, `404` если нет.

### `POST /api/v1/categories`

**Требует `admin`.** Тело: `{ "name": "Обувь", "slug": "obuv", "description": null }`.
`slug` опционален, генерируется из `name` по тем же правилам. `name`
уникален, `slug` уникален. Ответ `201`. `409` при дубле.

### `PATCH /api/v1/categories/{id}` — **требует `admin`**, частичное
обновление. `409`, если новый slug уже занят.

### `DELETE /api/v1/categories/{id}`

**Требует `admin`.** Ответ `200` `{ "message": "Категория удалена" }`.

Если в категории есть товары — `409` с сообщением о количестве.

## 5. Корзина

Все эндпоинты требуют авторизации. Корзина одна на пользователя,
создаётся автоматически при первом обращении.

**Контракт мутаций:** каждый метод, изменяющий корзину, возвращает
**всю корзину** в актуальном состоянии. Фронтенд заменяет своё
состояние целиком, а не точечно обновляет.

### `GET /api/v1/cart`

Ответ `200`:

```json
{
  "items": [
    {
      "id": 2,
      "product_id": 5,
      "product_name": "Джинсы прямого кроя",
      "product_slug": "straight-jeans",
      "image_url": "https://images.unsplash.com/photo-1542272604-787c3835535d",
      "size": null,
      "quantity": 2,
      "unit_price": "89.00",
      "line_total": "178.00"
    }
  ],
  "total_items": 2,
  "total_price": "178.00"
}
```

Поля позиции:

| Поле           | Тип    | Примечание |
| -------------- | ------ | ---------- |
| `id`           | int    | id позиции, для `PATCH`/`DELETE` |
| `product_id`   | int    | для ссылки на карточку товара |
| `product_name` | string | денормализовано, чтобы не грузить товары |
| `product_slug` | string | |
| `image_url`    | string | |
| `size`         | string | либо `null` |
| `quantity`     | int    | 1–99 |
| `unit_price`   | string | цена на момент добавления |
| `line_total`   | string | `unit_price × quantity` |

`total_items` — сумма quantity. `total_price` — сумма `line_total`.
Пустая корзина: `items: []`, `total_items: 0`, `total_price: "0.00"`.

### `POST /api/v1/cart/items`

Тело:

```json
{ "product_id": 3, "quantity": 2, "size": "M" }
```

`quantity` 1–99 (по умолчанию 1), `size` опционален.

Поведение:

- Если позиция с тем же `product_id` и тем же `size` уже есть —
  количество **складывается**, новая позиция не создаётся.
- Разные размеры — разные позиции.
- `size` проверяется по списку `product.sizes`. Если у товара список
  размеров пуст, любой размер игнорируется (товар без размеров).
- `quantity` сверяется с остатком: и новое, и суммарное количество не
  должно превышать `product.stock`.

Ошибки: `404` — товар не найден; `400` — размер недоступен или товар
неактивен; `409` — превышение остатка.

**Цена фиксируется в момент добавления.** Последующее изменение цены
товара не влияет на уже лежащие в корзине позиции.

### `PATCH /api/v1/cart/items/{item_id}`

Тело: `{ "quantity": 4 }`. Проверка остатка. `404` — позиция не найдена.

### `DELETE /api/v1/cart/items/{item_id}`

Возвращает корзину без удалённой позиции. `404`, если позиции нет.

### `DELETE /api/v1/cart`

Полная очистка. Возвращает пустую корзину.

## 7. Модель данных

```
user ──1:1── cart ──1:n── cart_item ──n:1── product ──n:1── category
```

**category**: `id` PK, `name` (уникальный), `slug` (уникальный),
`description` (nullable), `created_at`, `updated_at`.

**product**: `id` PK, `name`, `slug` (уникальный), `description`,
`brand` (nullable), `price` decimal(10,2), `discount_percent` (nullable),
`image_url`, `images` (массив строк, не пустой), `sizes` (массив строк),
`colors` (массив строк), `stock`, `is_active`, `category_id` FK
(не nullable, `ON DELETE RESTRICT`), `created_at`, `updated_at`.

**user**: `id` PK, `username` (уникальный), `email` (уникальный),
`hashed_password`, `full_name` (nullable), `role` (enum: `user`/`admin`),
`is_active`, `created_at`, `updated_at`.

**cart**: `id` PK, `user_id` FK (уникальный — одна корзина на
пользователя), `created_at`, `updated_at`.

**cart_item**: `id` PK, `cart_id` FK (cascade delete), `product_id` FK,
`quantity`, `unit_price` decimal(10,2), `size` (nullable),
`created_at`, `updated_at`. Уникальность по
`(cart_id, product_id, size)`.

### Обязательные инварианты

- Пароли хранятся только в виде хеша (argon2/bcrypt/argon2id). Открытый
  пароль в БД недопустим.
- `final_price` не хранится — только вычисляется.
- Денежные значения — `DECIMAL`, не `FLOAT`/`INTEGER`.
- Ограничения целостности на уровне БД: `price >= 0`, `stock >= 0`,
  `0 <= discount_percent <= 100`.
- Удаление категории с товарами запрещено — реализовать на уровне БД
  (`RESTRICT`) или явной проверкой с возвратом `409`.
- Роли: `user` — чтение каталога и работа со своей корзиной;
  `admin` — создание, изменение и удаление товаров и категорий.

## 8. Демо-данные

Для проверки фронтенда нужны категории с ожидаемыми slug, иначе фильтры
на страницах разделов вернут пустоту. Минимальный набор:

| Категория        | slug          |
| ---------------- | ------------- |
| Мужская одежда   | `men`         |
| Женская одежда   | `women`       |
| Детская одежда   | `kids`        |
| Аксессуары      | `accessories` |

Товаров — 6+, у каждого `image_url` с Unsplash (домен разрешён в
конфигурации изображений), заполнены `sizes`, `colors`, `brand`,
`stock`. У части товаров `discount_percent` задан, чтобы на витрине
были видны перечёркнутые цены.

Учётные записи: `admin/admin12345` (роль `admin`) и `demo/demo12345`
(роль `user`).

## 9. Что фронтенд шлёт на практике

Реализовывать нужно весь контракт, но на ручную проверку попадёт в
основном следующее — полезно знать исполнителю.

**Фильтры каталога.** Главная шлёт `search` и `category` из query-строки
плюс `limit: 40`. Страницы разделов шлют `category` (slug) и `search`.
Реально проверяются `search`, `category`, `limit`. Остальные параметры
(`offset`, `min_price`, `max_price`, `in_stock`, `sort`) в UI пока не
выведены, но контракт их поддерживает — понадобятся при расширении.

**Регистрация.** Флоу двухшаговый: сначала `POST /users/register`, затем
`POST /users/login`, затем `GET /users/me`. Авто-логин после регистрации
возвращать не нужно — фронтенд перезайдёт сам.

**Корзина.** При выборе размера на карточке товара отправляется `size`.
Если размер не выбран (у товара пустой список размеров) — поле
отсутствует. Схема обязана это допускать: `size` необязателен.

**Избранное.** На фронтенде есть кнопка сердечка, визуально она ничего
не делает. Эндпоинтов избранного в контракте нет. Реализация сверх
задачи не помешает, но и не требуется.

## 10. Definition of Done

- [ ] `GET /api/v1/products` возвращает конверт `{items, meta}`,
      фильтры `search`/`category`/`min_price`/`max_price`/`in_stock`
      и все значения `sort` работают; `meta.total` учитывает фильтры.
- [ ] `final_price` считается с округлением до копеек, при `null` скидке
      равен `price`.
- [ ] Создание товара генерирует slug из кириллического названия,
      при коллизии добавляет суффикс.
- [ ] Регистрация, вход, refresh, `me` работают; access- и
      refresh-токены взаимно не принимаются.
- [ ] Ответ на неверный пароль и на несуществующий логин неразличимы.
- [ ] Пароль и его хеш не попадают ни в один ответ.
- [ ] CRUD товаров и категорий требует `admin`; обычный пользователь
      получает `403`.
- [ ] Фильтр по категории указан **slug**, а не id.
- [ ] Удаление категории с товарами даёт `409`.
- [ ] Повторное добавление того же товара и размера складывает
      количество; разные размеры дают разные позиции.
- [ ] Цена фиксируется при добавлении в корзину.
- [ ] Превышение остатка даёт `409`, недоступный размер — `400`.
- [ ] Пустая корзина возвращает `total_price: "0.00"`, а не 404.
- [ ] `/health` отвечает без аутентификации.
- [ ] В ответе 500 нет внутренних деталей.
